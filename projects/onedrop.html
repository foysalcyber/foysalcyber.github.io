// THE PROBLEM

In an emergency, finding blood in Bangladesh still runs on Facebook groups and phone trees. A family learns at 9 pm that a parent needs O− by morning, then starts calling strangers from a screenshot three months old. Lists go stale, donors sit 40 km away when a match lives on the next street, and phone numbers are posted in public — which is exactly why many willing donors quietly stop listing themselves at all.

// THE APPROACH

I built it the way a security engineer builds anything: store the minimum, verify what you show, and let the rules — not the interface — enforce the boundary. Anonymous Firebase sessions mean a donor never hands over an email or a password. Every listing is bound to its own UID, and Firestore rules allow writes only to your own record, over an allowlisted field set. Phone numbers are never rendered in the directory markup: they are fetched on demand, one tap at a time, and every browser is capped at 25 reveals an hour. Matching is distance-first, with the district centroid as an honest fallback when GPS is denied.

// THE RESULT

A live, installable PWA that the whole network can use with zero onboarding: search without signing up, alert volunteers within seconds, and a moderation workspace where moderators can approve, verify and publish — but never delete or edit a record. That limit lives in the security rules, not in a hidden button. Seventy automated checks run against a local server with every Google host blocked, so the offline path, the demo dataset and the privacy guarantees are proven on each change — and nothing in the test suite ever touches the live project.

File 121 · Build Notes
Engineering decisions
Identity

Anonymous Firebase sessions: a donor can list themselves, edit their listing and log a donation without ever creating an account. The listing is scoped to that anonymous uid, so my-donor.html can only ever touch its own record.

Read vs reveal

The directory query returns name, group, district and an approximate distance — never a phone number. Contact is a separate, deliberate action: one tap, one number, 25 an hour per browser, which is what keeps scrapers and spam out of the network.

Authorisation

Moderation is a role, not a UI state. Moderators can approve requests, verify donors and publish notices, restricted by changedOnly(...) so nothing else in a document can be modified. Deletes belong to the owner account alone — and the rules are published in the repo, so anyone can audit them.

Location

GPS is optional and never shared raw. The public UI shows only a distance; without GPS the app falls back to the district centroid, which is honest about its accuracy instead of pretending to be precise.

Failure modes

If Firestore cannot be reached, the app keeps working from cache; if there is no cache at all, a clearly-labelled demo dataset renders so a visitor is never met with an empty page — and never mistakes demo data for a real donor.

Measurements

Daily counters (visits, requests posted, registrations) are written anonymously — one write per visitor per day. No third-party analytics, no ad pixels, no cookie banner, because there is nothing to consent to. Requests queued offline sync when the connection returns.
